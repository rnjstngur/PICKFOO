# PICKFOO 통합 업그레이드 · 사용설명 (2026-11-05)

## 포함한 기능
- 기존 음식 조합/리뷰/사진 수정·삭제/추천/구매 앱 열기 기능의 코드 유지. 외부 앱 검색어 복사 도우미 추가.
- PostgreSQL `points_pointentry` 추가: 사진 있는 DB 리뷰 **최초 업로드 시** 10P 적립.
- 같은 사용자·같은 조합은 사진 교체나 리뷰 삭제 후 재작성해도 **추가 적립 없음**.
- DB 포인트 조회/내역 및 가상의 포인트 상점 교환(API 포함). **실제 상품 지급 아님**.
- 리뷰 사진 열람에 서버측 소유자 검증(리뷰 작성자 또는 조합 소유자). 개발 사진을 `/media/` 공개하지 않음.
- Django와 `www`를 **동일한 8000 포트**에서 서비스하는 방식 제공 (WhiteNoise).
- 클라우드 DB 환경변수/Dockerfile/선택형 비공개 S3 저장소 설정.
- 최신 웹 파일이 Android assets/public에도 반영되어 있으며 Capacitor sync도 지원.

## 1. Windows에서 실행 (권장: 같은 포트 방식)
1. 기존 원본 PICKFOO는 보관하고 이 통합본을 다른 폴더에 압축 해제한다.
2. Python 3.12 이상, PostgreSQL, Node.js(안드로이드만)를 준비한다.
3. `backend/.env.example`을 복사하여 `backend/.env`를 만들고 `DB_PASSWORD`와 `DJANGO_SECRET_KEY`를 설정한다.
   - 키 생성: `py -c "from secrets import token_urlsafe; print(token_urlsafe(50))"`
4. CMD에서:
   ```cmd
   cd /d C:\devpickfoo\PICKFOO_TEAM_SHARE\backend
   py -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   .venv\Scripts\python.exe manage.py migrate
   .venv\Scripts\python.exe manage.py check
   .venv\Scripts\python.exe manage.py runserver
   ```
5. **http://127.0.0.1:8000/index.html** 접속. 이 방식은 프론트/백이 같은 주소라 Android 테스트에 유리하다.
   - 예전 `www`용 8765 포트 방식도 `pickfoo-api-config.js`로 지원한다.
   - `migrate`는 기존 표들을 삭제하지 않고 `points_pointentry` 등 신규 표를 추가한다.

## 2. Android Studio에서 실행 (PC에서 에뮬레이터로 테스트)
1. Django를 `...manage.py runserver 0.0.0.0:8000`으로 실행한다.
2. 프로젝트 루트에서 CMD:
   ```cmd
   py scripts\configure_android.py emulator
   npm ci
   npx cap sync android
   npx cap open android
   ```
3. Android Studio에서 가상 기기를 선택해 ▶ 실행. 에뮬레이터의 `10.0.2.2`는 PC 개발 서버를 가리킨다.
4. 개발 모드는 HTTP 허용 설정이 포함된 **디버그 빌드 전용**이다.
5. **중요**: `server.url`은 Capacitor의 라이브 리로드/개발 전용 설정. 마켓용 출시에는 그대로 사용하면 안 된다.
6. 다시 `www` 내부 파일 포함 모드로 되돌리려면:
   ```cmd
   py scripts\configure_android.py packaged
   npx cap sync android
   ```
   단, 이 패키징 모드에서는 배포된 Django HTTPS 서버의 주소/인증 쿠키 처리를 별도로 연결해야 한다.

## 3. 클라우드 운영 설정 (프로젝트에 배포 템플릿 포함)
- Django 서버 배포 업체에 Dockerfile을 연결하고 **환경변수**를 입력한다.
- `DJANGO_DEBUG=false`, `DJANGO_SECRET_KEY=<보안키>`,
  `DJANGO_ALLOWED_HOSTS=<실제도메인>`, `DATABASE_URL=<클라우드Postgres 접속URL>`,
  `DATABASE_SSL_REQUIRE=true`(해당 DB 공급자가 요구하면), `DJANGO_TRUST_PROXY_HTTPS=true`(HTTPS 프록시 신뢰할 수 있는 경우에만).
- 서버 시작 전에 `python manage.py migrate`를 실행하는 *release command*를 설정한다.
- 개발용 비공개 사진은 로컬 `backend/media`에 저장되므로 서버 재배포 때 소실 가능.
  실제 서비스는 **비공개 S3-compatible 스토리지** 설정 권장:
  `PICKFOO_MEDIA_STORAGE=s3`, `AWS_STORAGE_BUCKET_NAME`, `AWS_S3_REGION_NAME`,
  `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (필요 시 `AWS_S3_ENDPOINT_URL`).
- **운영용 DB·S3·도메인·HTTPS 발급 및 결제/계정 생성은 사용자 직접 설정 필요**.
- Docker 테스트는 빌드까지 수행 가능하나 운영 배포가 자동 완성되지는 않는다.
- 사용자가 선택한 도메인과 DB 연결정보를 Android APK에 노출하지 않도록 주의한다.
- Android의 최종 배포(서명키, API 연결, 로그인 쿠키 테스트, Play 정책 등)는 별도 검증 필요.

## 4. DB 포인트 정책
- 서버에 사진이 성공적으로 업로드된 **최초 1회** 적립 (한 회원/조합당).
- 기존에 저장한 사진에는 마이그레이션 시점에 **소급 적립하지 않음**.
- 리뷰 수정/사진 교체/삭제·재작성에 추가 적립 없음; 이미 지급한 포인트도 삭제할 때 회수하지 않음.
- 기존 샘플 조합 리뷰의 localStorage 데모 포인트는 DB 포인트와 **별개**이며 통합되지 않음.
- DB 포인트 상점은 시연용 기록만 남고 실제 쿠폰 지급·발송 없음.
- 실제 보상 지급 전에는 약관, 악용방지, 회수/중복 정책, 관리자 검수 기능 등을 추가해야 함.

## 5. 현재 제약 / 직접 마무리해야 할 항목
- 클라우드 계정/도메인, 운영 DB 및 사진 저장소의 실제 개설과 연결은 미완료.
- Android 실제 기기/스토어 출시 APK는 검증되지 않음 (에뮬레이터 개발 모드부터 테스트).
- **배민/요기요/GS25 등 외부 앱 메뉴 자동 검색 및 자동 장바구니**는 공식 API/딥링크 지원이
  확인되지 않아 구현하지 않음. 기존 외부 앱 열기와 상품 검색어 복사 버튼은 제공하지만, 검색창에 직접 붙여넣어야 함.
- 개발/시연 단계의 로그인, 공개 운영 보안, 개인정보 정책, DB 백업/감사/속도 제한은 추가 검토 필요.
- 음식 재료 및 알레르기 정보는 부분 입력이며 **안전 인증이 아님**.

## 6. 확인 명령
```cmd
cd backend
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py test points catalog
```
- 로그인 후 `/api/points/`가 JSON을 반환하면 DB 포인트 조회 라우팅 성공.
- Django 서버가 `index.html`을 직접 제공하고 로그인/리뷰/포인트 화면을 정상 로딩하는지 확인.
