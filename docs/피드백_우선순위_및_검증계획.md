# PICKFOO - 중간발표 피드백 실행 계획 (출처: 팀 제공 2026-11-03 정리 문서)

## 현황을 정확히 구분하기
- 이 ZIP에 있는 실제 동작 코드는 정적 웹 + Capacitor + localStorage입니다. 교수님 피드백에 언급된 Django/SQLite 서버 구현본은 이 ZIP 안에 없습니다.
- 이번 정리본에서 실제 추가한 것: 외부 SDK 제거(기본 오프라인 시연), Python 간단 서버, Windows/Mac/Linux 실행 도우미, 취향 규칙 정렬, 추천 규칙 자동 테스트, 시연 데이터 표시 정직화.
- 계획만 있는 것: SNS·외부 후보 실수집, 추세 기반 트렌드 지표, 다중 사용자 실제 검증, 서버 기반 계정/리뷰/포인트, 동시성 검사, 구매 주문 연동.

## 지표 정의(확정 기준은 팀 실험 후 결정)
- 예시 트렌드 정책: 최근 7일 고유 반응 U7, 직전 7일 Uprev7을 분리, 변화량 U7-Uprev7과 누적 평가/검증을 따로 표시.
- 중복 반응 제외: (사용자ID, 조합ID, 이벤트종류, 기간) 단위 정책을 사전에 문서화.
- 개인화 비교: 프로필 A/B에 대해 같은 후보, 같은 정렬 조건을 사용해 추천 1~3위 결과 비교. 가중치는 실험 후 조정.
- 배지는 단순 사진 제출을 인증으로 여기지 않으며 '서비스 내부 평가 기준 만족'으로만 표현.
- 주의: 원문에 없는 조회수/좋아요를 만들지 않고, 앱 내부 이벤트는 '앱 내부 반응'으로 표기.

## 발표 시 빠뜨리지 말 것
1. 시연용 예시 데이터와 실제 수집된 데이터 분리.
2. 로컬 시연과 서버 연동 완료의 차이 설명.
3. 무엇을 구현했는지/검증했는지/계획 중인지 구분.
4. 네트워크 실패, 검색 결과 없음, 조건 만족 후보 0개 화면도 보여주기.
5. 구매 연동은 현재 보류이고 교수님 핵심 평가 요구 중 하나로 남아 있음을 인정하기.

최종 평가 일정/지도교수·팀 명/구성원은 팀에서 최신 공지로 확인.
